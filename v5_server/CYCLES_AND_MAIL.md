# 周期、自动邮件与卡池轮换

管理员登录后台后，在“周期与自动化”配置对策协议、多维变量、卡池轮换及等级成长礼包。手动邮件的有效期在“邮件系统”设置。

## 默认规则

- 对策协议每 42 天一轮。首次迁移保留已有等级、付费档位及领取记录；真正到达周期结束时归档上一轮并重置该轮经验、付费档位、任务及领取记录。修改天数从下一轮生效。
- 多维变量（矩阵肉鸽）默认每 7 天一周期，锚点为每周一 05:00。客户端活动倒计时取本轮真实起止时间，不再下发 2047 年远期兜底；起止时间由 `sc_11003` 与 `sc_11001` 中 template 73 的活动条目共用同一窗口。修改天数从下一轮生效，本轮窗口与已有探索记录不变。其他活动的远期兜底时间保持原样，避免连带影响版本隔离与解锁判定。
- 日常任务每天服务器当地 05:00 刷新，周常任务每周一 05:00 刷新。战令任务的截止时间不超过本轮结束时间。周期记录持久化，离线跨多轮及服务器重启不会重复重置；永久任务和其他养成不清空。
- 卡池默认每 7 天换一组，依次为当前卡池、与破晓凯旋、天通明晦、莫道奈何，然后循环。常驻、钥从、新手和目前两个自选池保留在固定组中。可修改天数、第一组起始时间、固定池及轮换顺序，或停用轮换。轮换不修改已有保底、自选目标和抽卡记录。
- 新邮件默认有效 30 天，支持有效天数（1 至 3650）或指定未来截止时间。过期普通邮件不再出现在游戏收件箱，不计入未读数量；单领、一键领取及收藏邮件都不能领取已过期附件。收藏正文及后台历史保留。
- 默认 11 至 100 级成长礼包每个已注册账号投递一次，现有符合条件的账号也补发一次。礼包含精确探测凭证（38）20 张、艾因索菲币（2）200000、高级作战记录（40103）30、神力因子（40301）50、次级权能因子（41301）30，有效期 30 天。数量、等级范围、正文及有效期均可修改。新建规则可取消对已有达标账号的补发。

后台每 30 秒检查轮换和未完成的邮件投递。登录或升级事件也会检查等级规则。邮件与发放记录一起提交，失败可重试；删邮件、编辑规则、停用再启用或重启服务不会重复投递同一规则。附件仍须在游戏内领取才会增加资产。等级上限也参与匹配，因此“达到 11 级即可领”的规则应使用 11 至 100 级。

轮换启用时，手动上架状态会在下一次检查时恢复为已保存的轮换组。建议将运行时区设为 `Asia/Shanghai`（UTC+8）；轮换起始时间显示为服务器时间，手动邮件的日期选择使用浏览器本地时间。

局内「维度偏移」历程的周期与上面的显示窗口同源：`polyhedron_service.PolyhedronRunManager.get_policy_cycle_id` 直接取本轮窗口起点，不再有独立的 `1700000000` 基准。`polyhedron_meta.cycle_id` 由迁移补充（`_COLUMN_MIGRATIONS` 幂等补列），存量账号补列后为 0，登录时只写入锚点、不清任何进度；此后每到窗口起点，才重置该账号该活动的历程经验（货币 45）与已领取记录，终端经验（46）、已点亮天赋、解锁英雄与信标、最高难度通关记录全部永久保留。此前该列并不存在，旧版本缺少该列时无法保存周期标记；迁移后从下一周期边界开始重置。

## 管理接口

| 接口 | 内容 |
| --- | --- |
| `GET /api/gm/automation/status` | 当前周期、下一次刷新时间、轮换状态、等级规则及后台检查状态 |
| `POST /api/gm/automation/schedule` | `battlepass: {duration_days}`、`polyhedron: {duration_days}` 或 `rotation: {enabled,duration_days,start_ts,fixed_pool_ids,steps}` |
| `GET /api/gm/mail/rules` | 等级规则、已发/待发数量及近期失败记录 |
| `POST /api/gm/mail/rules` | 新建或使用 `id` 编辑规则；含 `level_min,level_max,enabled,attachments,valid_days,title,sender,content` |
| `POST /api/gm/mail/send` | 原有邮件字段，附加 `valid_days` 或 `expire_time`，两者不能同时提供 |

所有管理接口沿用管理员认证。规则编号永久保留发放记录；若要给同一账号发送另一份礼包，应新建另一条规则。

配置存于 `server_global_config`；周期标记与历史存于 `battlepass_cycle`、`battlepass_cycle_history`、`task_cycle`；发放记录与失败记录存于 `gm_level_mail_delivery`、`gm_level_mail_failure`。迁移不恢复或整体替换玩家数据库。

## 验证

使用完整的隔离测试数据库（管理员未初始化），设置 `GM_TEST_DB_SEED` 后运行 `python -m unittest discover -s tests -v`。
测试会再复制种子到临时目录；不要使用运行中的玩家数据库。种子不随源码发布。
