# GM 管理功能

支持资源背包、角色操作和抽卡规则管理。游戏内刻印、钥从的堆叠和仓库容量沿用原实现。

## 已实现

- **资源背包**：读取真实货币、材料、碎片、刻印和钥从；点击图标选择物品并直接发放。可选择按指定星级发放完整六槽位刻印套装。
- **闲置实例清理**：先预览实例 ID 和数量，再输入当前 UID 确认。仅删除未锁定、未装备、未培养且符合星级条件的刻印或钥从，不返还材料；提交时重新检查保护条件。每次最多 1000 件。
- **角色操作**：解锁当前角色、解锁当前可用图鉴、基础养成满级。解锁操作幂等，不会把重复点击变成碎片发放。基础满级为等级 80、Ω、技能 35、权钥 60、受支持的武器模组上限；不更换刻印、钥从、皮肤或誓约。
- **抽卡规则**：分四个系列保存基础出金率、软保底起点、硬保底次数、A/四星条件概率及保底、扩充池 UP 比率和服务端扣券倍率。保存及恢复默认不清空已有保底进度。
- **备份**：使用 SQLite 在线备份接口，包含 WAL 中已经提交的数据；每个备份使用独立文件名并检查完整性。
- **配置刷新**：刷新物品和卡池数据缓存；Python 代码更新仍需重启服务，不再把缓存刷新表述为代码模块热替换。

物品发放和角色更新在事务提交前生成必要同步数据，失败时回滚。提交后的网络推送失败会明确提示重新登录，不把已完成的发放重做一次。只向已完成登录初始化的对应 UID 连接推送。

普通物资单次最多发放 999999999 个；独立实例资产单次最多 200 件，六件套最多 33 套。这是 GM 操作批量限制，不是游戏内堆叠上限。唯一解锁物品继续走原有转换规则。

抽卡默认规则保留原实现：S 基础率 1.6%，70 抽系列从第 66 抽提升概率，90 抽系列从第 81 抽提升；扩充池出金 50% 命中 UP，歪后下次出金必 UP。A/四星默认保底为 10 抽。

自定义抽卡参数存于 `server_global_config` 的 `gm_draw_rules_v1`，仅管理员保存后变化。规则影响服务端实际抽取；客户端固定概率说明、消耗提示及发起抽卡的余额判断可能仍采用原版配置，GM 页面会提示这一边界。

## 接口

| 接口 | 用途 |
| --- | --- |
| `GET /api/gm/inventory/items?uid=...` | 真实资产及实例信息 |
| `POST /api/gm/inventory/add_item` | `uid,item_id,num` 发放 |
| `POST /api/gm/inventory/add_suit` | `uid,suit_id,star,count` 六件套 |
| `GET /api/gm/inventory/cleanup_preview` | `uid,category,max_star` 预览 |
| `POST /api/gm/inventory/clear` | `confirm:true`、预览实例 ID 列表及对应条件 |
| `POST /api/gm/heroes/unlock` | 指定角色或 `all:true` |
| `POST /api/gm/heroes/graduate` | 当前角色基础养成满级 |
| `GET/POST /api/gm/gacha/rules` | 查询、保存或恢复系列规则 |

角色、物品 ID 均依据当前服务端已有资产配置验证；失败不会降级成错误的货币入库。

## 构建与验证

前端在 `web_src` 内运行 `npm ci`、`npm run check`、`npm run build` 和 `npm run build:sub`。
构建产物位于 `static_web`。账号与玩法回归测试需要完整的隔离数据库种子，通过 `GM_TEST_DB_SEED` 指定；种子不随源码发布。
