# 礼物盒子与旧情报箱发奖修复

背包使用“礼物盒子”（30011）时，旧实现把参数 `[10, 4]` 当作道具编号与数量，每盒发出 4 个“秘钻”，其客户端配置没有图标。现在按参数指定的道具类型与稀有度，从客户端配置的 65 种四星礼物中独立抽取，每盒产出一份，并合并回复中的重复奖励。

三种旧修正者情报箱（30002/30003/30004）使用同一规则，分别从 61/21/2 种对应 S/A/B 级情报中抽取，每盒产出一份情报。奖池导出自同版本 ItemCfg 和 HeroCfg，并与完整测试库目录逐项核对。

随机箱拒绝客户端自选项；使用配置或奖池缺失、参数不匹配时返回失败。扣料、发奖和必要回复由已有事务保存点保护，执行中失败恢复整个请求。

验证：17 项开箱专项和 48 项资产、回执相关检查全部通过，使用独立数据库副本，包含完整奖池、真实随机抽取、混合开箱、扣料合计、故障注入、嵌套调用、另一 UID 和持久化核对。本批完整服务端回归与全量问题清单按累计批次统一处理。
