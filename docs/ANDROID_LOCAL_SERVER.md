# 安卓游戏与服务端同机运行

连接助手 **1.1 正式版**增加手机本地模式，让游戏的 SDK HTTPS 443 和辅助 HTTP 80 经本地 VPN 转到同机 Termux 的 8443 和 8080。服务端使用 `--android-local` 向客户端下发本机地址，网关、游戏 TCP 和战斗 UDP 直接使用高位端口。

2026-11-01 已在 vivo（Android 16 / API 36）成功完成 Unity 客户端同机登录，并通过战场清扫关卡的实际战斗与结算。1.1 沿用这次实测通过的连接逻辑，服务端日志记录了本机 gateway/game 鉴权、登录洪流、心跳和战斗结果。这一阶段仍沿用原资源下载地址。

## 准备本机实例

需要 [用户 CA 版客户端](ANDROID_SETUP.md)、ARM64 连接助手 1.1、自己的完整数据库，以及与客户端对应的资源清单。公开测试种子只用于技术验证，不能替代可游玩的完整存档和资源。

将当前源码放入 Termux 可读目录。服务端依赖 Python、Flask 和 cryptography；已有 Linux/PRoot Python 环境可按 `v5_server/requirements.txt` 安装。直接使用 Termux 时可准备：

```sh
pkg install python python-cryptography clang
python -m pip install flask
```

首次创建新的本机实例、尚未配置自己的根证书和私钥时，在项目目录生成自己的 CA：

```sh
python v5_server/gen_cert.py --out v5_server --force-ca
```

源码附带的公开证书不含对应私钥。这条命令会生成新的根证书，需要在手机重新安装；已有自己的完整证书体系时继续复用，正常启动不会更换根 CA。

按 [账号设置说明](../v5_server/ACCOUNTS.md) 准备自己的账号。把完整数据库放在 Termux 可读取的位置，从项目目录启动：

```sh
python v5_server/main.py --android-local --db /path/to/account.db --res-version 321
```

这里的 `321` 是当前 `v0.308.301` 客户端对应的资源构建号。使用其他客户端时须配置它对应的 Android 清单。资源和清单已经完整准备好、需要禁用服务端官方 CDN 抓包时，可以额外传入 `--no-capture-cdn`；这不会自动补齐游戏所需的资源。

启动输出应显示客户端下发地址和本机监听地址均为 `127.0.0.1`，证书安装地址为 `http://127.0.0.1:8080/cert`。保持这个服务端进程运行。

## 连接游戏

1. 从 [1.1 发行页](https://github.com/qiuyuxc/Alpha-Persei-Cluster/releases/tag/android-connect-v1.1) 下载并安装 `AlphaPersei-Connect-v1.1.apk`。正式包沿用已有助手签名，可在 ARM64 设备覆盖既有版本。
2. 用手机浏览器打开 `http://127.0.0.1:8080/cert`，下载并在系统安全设置中安装这个本机服务端的 CA。也可以直接取 `v5_server/sdk_ca.crt` 安装。
3. 停用其他 VPN 和既有 DNS 改写，将系统“私人 DNS / 私有 DNS”设为“关闭”。
4. 在助手中选择“连接方式 → 手机本地”，点击“开启连接”并允许系统 VPN 请求。
5. 完全退出并重新打开用户 CA 版游戏，用本机服务端的账号登录。保持 Termux 和助手后台运行。

“连接已开启”表示助手运行。实际登录以游戏结果为准；“连接诊断”中的本机转发连接和失败计数可用于定位链路问题。停止助手会关闭 VPN 和转发；服务端独立运行，退出服务端可在 Termux 按 Ctrl+C。

## 后台运行与厂商调度

同机运行时，游戏、Termux 服务端和连接助手需要同时存活。按机型的系统设置，允许 **Termux 和连接助手**后台运行、自启动，并放宽电池优化；最近任务支持锁定时可保留这两个应用。只保护助手，服务端仍可能受到后台限制。

如果切换到游戏后出现响应变慢或断连，可先尝试分屏或小窗保留 Termux，比较服务端响应是否改善。分屏、小窗是否可用取决于机型和游戏支持。部分厂商对后台进程的调度可能影响服务端，但本轮尚未进行不同后台状态的对照测试，不能认定所有机型都必须让 Termux 保持前台。

需要减少设备休眠影响时，在 Termux 会话中执行 `termux-wake-lock`，结束测试后用 `termux-wake-unlock` 释放。唤醒锁不能保证系统不回收进程，也不能替代电池优化和后台运行设置；分屏、小窗与这些设置的效果仍需按机型验证。

## 地址与端口

| 用途 | 游戏访问 | 本机服务端监听 |
| --- | --- | --- |
| SDK HTTPS | 原域名，虚拟地址 `10.111.0.3:443` | `127.0.0.1:8443` |
| SDK 辅助 HTTP | 原域名，虚拟地址 `10.111.0.3:80` | `127.0.0.1:8080` |
| gateway TCP | `127.0.0.1:8102` | `127.0.0.1:8102` |
| game TCP | `127.0.0.1:8105` | `127.0.0.1:8105` |
| battle UDP | `127.0.0.1:6105` | `127.0.0.1:6105` |

本地模式固定使用 8443/8080，所有监听都限制在本机。gateway、game 和 battle 可改为其他高位端口，服务端会下发对应值；各 TCP 监听端口不能重复。此模式不启动 53 端口 DNS，解析由连接助手处理。

服务端的客户端下发地址与 CDN 出站地址分别配置。本地模式下，CDN 出站按实际网络自动检测；必要时用 `--cdn-source-ip` 指定手机真实网络 IPv4，例如 Wi-Fi 地址。回环地址和助手内部地址不能作为 CDN 出站地址。

助手只转发原始 TLS 字节，客户端继续校验证书链和原域名。资源域名沿用实际网络 DNS；资源未准备齐时需要网络。本轮验证不等于完整断网运行验收。

## 验证范围

专项验证覆盖本机 HTTP/HTTPS 绑定、证书和主机名校验、端口冲突清理、外部模式兼容、本地流量分段/乱序/重传、停止和重启。模拟客户端已验证经原生协议栈和 Java 转发访问实际 V5 SDK，再使用真实 protobuf 完成 gateway 和 game 登录应答。

本轮真机已验证助手连接、Unity 同机登录、战场清扫关卡的战斗与结算。不同机型的后台调度、长时间保活、完整资源下载、Wi-Fi/移动网络切换及完整断网运行尚未统一验收；单一设备和单类关卡的结果不代表这些场景都已通过。
